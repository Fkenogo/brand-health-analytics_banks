## B. Problems Found

### B1. Weak driver explanation

`brandEdgeDriverSummary` (line 3089–3090) is generated by `summarizeBrandEdgeDrivers()` in `brandEdgeScore.ts` (line 37–39):

```ts
return `Awareness is ${strengthLabel(metrics.awareness)} at ${metrics.awareness}%,
loyalty is ${strengthLabel(metrics.loyalty)} at ${metrics.loyalty}%,
and switching pressure is ${metrics.switchingRisk}% risk.`;
```

This is a template sentence, not an explanation. It restates raw values without interpreting them. Example output: `"Awareness is strong at 72%, loyalty is moderate at 48%, and switching pressure is 18% risk."` — a user already knows those numbers from the cards above.

This section is also AI-addon gated, meaning free and standard users see no driver explanation at all.

### B2. The Executive Summary Snapshot table has stiff, vague copy

Specific issues found in the table:

| Cell | Current text | Problem |
|------|-------------|---------|
| Usage "Signal" column | `Highest friction: [stageName]` | Technical word "friction"; stage names are backend labels (e.g. "Awareness→Trial") |
| Competitive "Signal" column | `Observed Win Rate X%` or `Proxy Balance X%` | "Proxy Balance" is internal terminology |
| Awareness "Immediate Focus" | "Increase top-of-mind conversion from the awareness base" | Static string, always shown regardless of data |
| Usage "Immediate Focus" | "Reduce drop-off at the highest-friction stage" | "drop-off", "friction" are jargon; also static |
| Loyalty "Immediate Focus" | "Increase committed share by converting potential and favors; reduce rejectors" | Reasonable but also static |
| Momentum "Headline KPI" | Shows just a number with no unit | Not self-explanatory |
| Demographics "Headline KPI" | `[dimension]: [segment]` — e.g. `Age: 25–34` | Fine but the dimension is sometimes a backend ID |
| Table header | "Signal" column header | "Signal" is too technical/backend; should be "Status" or "Trend" |
| All "Immediate Focus" cells | Static strings per module | These never change regardless of the actual data state |

### B3. Key Highlights is trend-data-dependent and often empty

`trendsDiagnostics.highlights` (used at line 3192) is a computed string array from `computeTrendForecastDiagnostics`. When fewer than 2 valid periods exist — which is common for newer datasets — the array is empty and the section shows:

> "Highlights will appear when valid trend data is available."

This is a large collapsible panel that often renders as a near-empty placeholder. The section also mixes "trend highlights" with the concept of "key business priorities", which are two different things.

### B4. The Cross-Module Health Indicators are useful but under-explained

Four `variant="diagnostic"` cards are shown:
- **Funnel Health**: shows `usageDiagnostics.positionLabel` and `funnelHealthDiagnosis`. The position label (e.g. "Leaky Bucket") is good — but the subtitle can be a long sentence that wraps awkwardly in the card.
- **Top Risk**: shows `competitiveDiagnostics.threats.rows[0].competitorBankName` as the value and `threatLevel` as subtitle. Showing a competitor bank name as the "value" of a card is confusing — the card reads as if the competitor is a metric, not a subject.
- **Forecast Readiness**: shows "Ready" / "Pending" with period count. Clear and correct.
- **Primary Gap Cohort**: shows `demographicDiagnostics.opportunities[0].segment` and `dimension | usageGap pp`. The `|` separator looks like a backend format string. The usage gap number alone ("23pp") needs context.

### B5. No score driver strip for non-AI users

The "What drives this score?" block is gated by `hasAiAddon` (line 3087). Standard users (the majority) see nothing between the 7 KPI cards and the summary table. There is no plain-language explanation of why the BrandEdge score is what it is unless the user pays for the AI add-on.

`summarizeBrandEdgeDrivers` exists and is already computed for all users — it is only hidden behind the AI gate. A better version of this function should be shown to all tiers.

### B6. The KPI card grid is awkward at 7 cards

Seven cards in a `md:grid-cols-2 xl:grid-cols-4` layout means the grid is uneven. The 7th card (Sample Size, `variant="secondary"`) breaks the row and looks like a footnote rather than a KPI. It is also styled differently, which calls attention to the mismatch.

### B7. No module navigation guidance

After viewing the 7 cards, a user has no prompt about which module to open next. The summary table has "View Report" buttons, but they sit at the far right of a dense 5-column table. There is no priority ordering — all modules are presented equally.

### B8. Trend readiness is buried and inconsistently labelled

- The "Forecast Readiness" card in the health indicators covers the forecast data story.
- But the "Key Highlights" section also relates to trend data.
- Neither section explicitly says "You need 2 completed survey waves to see trend tracking" in a prominent or early place.
- There is no clear visual separation between "what we know now" and "what will become available over time."

### B9. Backend IDs and technical labels found

| Location | Issue |
|----------|-------|
| `competitiveDiagnostics.threats.rows[0].competitorBankName` shown as card value | May include internal bank ID if name lookup fails |
| `usageDiagnostics.highestFrictionStage` in table | Stage names use internal string keys |
| "Proxy Balance" label in competitive signal column | Internal computation term |
| `demographicDiagnostics.opportunities[0].dimension` | Dimension values are internal category labels |

## C. Recommended New Overview Structure

### Section 1: Executive Brand Status (replace current 7-card grid)

Keep as a card grid but reorganise:
- **Primary row (4 cards):** BrandEdge Score · Awareness · Current Usage · Loyalty Index
- **Secondary row (3 supporting stats):** Momentum Score · NPS · Competitive Win Rate
- Sample size moves to the page header or a small footnote, not a KPI card

This keeps the visual density but removes the awkward 7th-card row break.

### Section 2: Score Driver Strip (ungated, all tiers)

Replace the AI-gated "What drives this score?" box with a computed, plain-language strip visible to all users.

New `summarizeBrandEdgeDrivers()` format:
- Identify the 1–2 weakest components of the BrandEdge formula (awareness × 0.3, usage × 0.3, loyalty × 0.2, primaryShare × 0.1, switchingRisk × −0.1)
- Generate a 2-sentence description: what is working and what is dragging the score down
- Example: "Awareness is reaching 72% of the market, which is a strong foundation. Usage and loyalty are below the threshold needed to push the score higher — these are the main drivers holding the score back."

This requires a new `buildBrandEdgeDriverNarrative()` function in `brandEdgeScore.ts` (no formula changes).

The existing `brandEdgeDriverSummary` + AI enhancement can remain as an additional layer for AI-addon users below this strip.

### Section 3: Module Health Cards (replace current summary table)

Replace the 5-column table with a 2×3 card grid — one white card per module:

```
[Awareness & Consideration]  [Usage & Behavior]
[Loyalty & Satisfaction]     [Brand Momentum]
[Competitive Intelligence]   [Demographics]
```

Each card:
- **Header:** module name
- **Primary metric:** headline value (large text)
- **Status badge:** derived from module diagnostics (e.g. "Strong", "At risk", "Steady")
- **One-line implication:** derived from the existing `moduleSummary.snapshot` (already computed per module)
- **Action link:** "Open report →"

Key improvements over current table:
- The `snapshot` field from each `moduleSummary` is already computed and available. Use it.
- Status badges can be derived from existing data without new computation.
- White cards on dark background are more readable than a compressed table.

Data sources (all already computed, no new memos needed):
- `awarenessModuleSummary.snapshot` → awareness card
- `usageModuleSummary.snapshot` → usage card
- `loyaltyModuleSummary.snapshot` → loyalty card
- `momentumModuleSummary.snapshot` → momentum card
- `competitiveModuleSummary.snapshot` → competitive card
- `demographicDiagnostics.highValueSegments[0]` → demographics card (no moduleSummary here — needs a small helper or inline text)

### Section 4: Priority Action Panel

A compact numbered list of 3–5 priorities derived from the data:

```
Priority actions
1. [action text]
2. [action text]
3. [action text]
```

Generated from a new `buildOverviewPriorityActions()` function that reads:
- `usageDiagnostics.highestFrictionStage` → retention/trial priority
- `loyaltyDiagnosticsView.segmentPcts.Rejectors` → rejector reduction
- `competitiveDiagnostics.threats.rows[0]` → competitive defense
- `trendsDiagnostics.forecast.eligible` → trend readiness state
- `demographicDiagnostics.opportunities[0]` → demographic targeting

This is **display logic only**. No new computation — just plain-language rendering of existing diagnostic outputs.

### Section 5: Executive Summary Snapshot (improve existing table)

Keep the table but fix:
- Rename "Signal" column header to "Status"
- Replace static "Immediate Focus" strings with data-driven text using `moduleSummary.snapshot` trimmed to 60 chars
- Replace "Highest friction: [stage]" with a human-readable label
- Replace "Proxy Balance" with "Win/loss estimate"
- Remove demographic dimension raw value — show segment and gap only

### Section 6: Cross-Module Health Indicators (improve cards)

Keep the 4 cards but fix:
- **Funnel Health**: value = position label (e.g. "Leaky Bucket"), subtitle = one-sentence implication (trim `funnelHealthDiagnosis` to 50 chars)
- **Top Competitive Risk**: rename from "Top Risk Signal". Value = competitor name as subject ("vs [Name]"), subtitle = threat level in plain language
- **Forecast Readiness**: keep as-is — already good
- **Primary Opportunity Segment**: rename from "Primary Gap Cohort". Value = segment (e.g. "Age 25–34"), subtitle = "Usage gap: Xpp" without the `|` separator

### Section 7: Trend Tracking Status

Replace the "Key Highlights" collapsible with a clean "Trend Tracking" section that has two states:

**State A — insufficient data (< 2 periods):**
```
Trend tracking
Trend tracking will become available after at least two completed survey waves.
Once active, this section will show wave-over-wave changes across all modules.
```

**State B — data available:**
Show the `trendsDiagnostics.highlights` items (already plain-language after our previous fix) but labelled as "Recent observations" not "Key Highlights".

## Summary of Findings

**Current state:** The Overview tab is functional but thin. It has the right skeleton (KPI cards + summary table + health indicators) but lacks interpretation, prioritisation, and decision-framing. The summary table is cramped and uses static, sometimes jargon-heavy copy that never adapts to the data.

**Key gaps:**
1. No plain-language "why is the score this number" explanation for standard users
2. Module summary insights are already computed but not surfaced in Overview
3. The summary table is stiff and data-inaccessible; module cards would be cleaner
4. Key Highlights is often empty and not semantically distinct from trend readiness
5. Cross-module health cards have subtitle formatting issues and technical label leakage
6. No priority ordering or "what to do next" guidance

**What is safe to do:** All new Overview content reads existing computed values. No new diagnostic computations are needed until Phase 3 (priority panel), which only needs a thin aggregation function. The BrandEdge formula, all module computations, trend computations, and export logic are untouched.

**Recommended implementation order:** Phase 1 → Phase 4 → Phase 2 → Phase 5 → Phase 3  
(Quick wins first; structural changes in the middle; new function last)
